# 按你的工作调整

如何确定项目、项目准则和要使用的 AI。这里的设置，只要在输入框里说一声，AI 都会替你更改（只有登录 AI 和 API 密钥需要自己处理）。

## 在已有的仓库中使用

把那个仓库的文件夹设为项目的“工作文件夹”。不需要搬动其中的内容。文件夹里的 `AGENTS.md` 和 `CLAUDE.md`，AI 也会照常读取。

之后要更改时：界面左上角的项目名 →“（项目名）的设置…”→“工作文件夹”的“选择”→“保存”。

AI 改写文件时不会征求确认。开始之前先用 Git 提交（commit）一次，就能分辨出 AI 的改动并撤回。

## 增加项目

每个仓库建一个项目。左上角的项目名 →“新建项目”，填入名称和工作文件夹，按“创建”。

每个项目都有“简介”，用一句话说明这个项目做什么。委托里没有写明属于哪个项目时，AI 会根据简介来选择；在该项目中工作的所有 AI 也会收到它。简介为空时，AI 会在下一次把委托放进该项目时自己写。你可以在项目设置里修改。

不再使用的项目，可以在项目设置的最下方归档。

## 项目准则

把交给 AI 决定的事、希望它先问你的事、不希望它做的事，用平常的句子写在项目设置的“项目准则”里。它会传达给这个项目中的所有 AI。

用途与 `AGENTS.md` 基本相同。只想在使用 alpacawork 时让 AI 读到的指示，写在项目准则里。

```text
做法：涉及外观的改动，动手之前先给我看示例并询问
交给 AI 的事：做法、测试、收尾，不用问，自行决定后报告
不做的事：未经批准，不要 push 到 GitHub，不要发布
```

项目准则是给 AI 的约定，并不是由系统强制执行的限制。想限制 AI 能接触的范围本身时，请分开使用工作用的电脑或操作系统用户。

## 要使用的 AI

| AI 智能体 | 需要什么 |
| --- | --- |
| Claude Code、Codex | 在各自的 CLI 中登录 |
| GitHub Copilot | 登录 GitHub CLI（`gh auth login`）。本体已附带 |
| Grok Build、pi | 登录或 API 密钥 |

在“设置（齿轮）→ 服务器”的“智能体”中启用要使用的 AI，然后按“保存”。想按工作区分使用时，写进项目准则（“实现用 Codex，检查用 Claude Code”）。

AI 的套餐和设置，直接沿用你现有的。费用也按套餐计算。

## 选择模型

输入框旁边选的模型，是负责对接的 AI 的模型。负责的 AI 用什么模型，写在委托或项目准则里（“这项工作用 opus 来做”）。

要添加新模型时，在“设置（齿轮）→ 服务器”的“智能体”中打开卡片，在“委托时可选的值”的 `model` 一行加上模型名，按“保存”。

## 提供 API 密钥

密钥不要写在输入框或界面里，请自己写进文件。

1. 在“设置（齿轮）→ 服务器”最下方的“环境变量文件”中确认位置（通常是 `~/.config/alpacawork/env`）。
2. 像 `ANTHROPIC_API_KEY=...` 这样一行写一个，并让其他用户无法读取：`chmod 600 ~/.config/alpacawork/env`
3. 重启 alpacawork（[停止与启动](manage.md#停止与启动)）。
4. 确认 AI 卡片的“额外的环境变量”中有这个名称。没有的话，加上并按“保存”。

## 同时运行的数量

起初最多有 8 个 AI 同时运行。用量消耗太快时，在“设置（齿轮）→ 服务器”→“高级选项”中调小“最大并发运行数”，按“保存”。
