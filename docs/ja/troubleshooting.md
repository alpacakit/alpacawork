# 困ったとき

画面が開けるなら、入力欄で AI に聞くのが早道です（「予約フォームのタスクが進まないのはなぜ？」）。AI は直し方の手順を読めます。

データの置き場（`~/alpacawork`）や記録のファイルを、自分で消してやり直さないでください。

## タスクが止まった

「対応待ち」のタスクは、AI の実行が止まっています。開くと、題の下に理由が出ます。

- 「失敗」: 「やり直す」か「止める」を押します。やり方を変えてほしいときは、ボタンの代わりに入力欄に書いて送ります。理由が利用上限やモデルの混み合いなら、上限が戻ってから「やり直す」を押すか、入力欄で「別のモデルでやり直して」と頼みます。上限が戻っても自動では再開しません。
- 「上限停止」: AI どうしの自動のやり取りが、決まった回数（初めは20回）に達しました。続けてよければ「続ける」を押します。
- ボタンが無い理由（「受領不明」「設定なし」など）: 出ている文を読み、入力欄で「続けて」などと指示します。意味は [止まった理由の言葉](reference.md#止まった理由の言葉) にあります。

## 送ったのに進まない

入力欄の上に送信の状況が出ます。押すと、窓口の AI との会話が開きます。

- 「送信中…」「順番待ち」「対応中です…」など: 待ちます。
- 「送れませんでした（理由）」: 理由を読んで直し、もう一度送ります。
- 「届いたか分かりません」: 会話を開き、「送り直す」か「取り消す」を押します。
- 「返事を受け取れませんでした」: 「送り直す」を押します。添付は送り直されないので、添付があった依頼は書き直して送ります。利用上限のときは、上限が戻るか、別のモデルを選んでから送ります。
- 「コーディネーターの起動に失敗しました。」: 下の「AI エージェントが使えない」を見ます。

## タスクが動いているか分からない

- 「作業中」の行の時間が増えていれば、AI は動いています。
- 「最後の出力が古い」: 止まったとは限りません。しばらく待ち、変わらなければ入力欄で聞きます。
- 行の「順番待ち」: 同時に動かす数の上限に達して、空きを待っています。
- 行の「T12 待ち」: T12 が終わるのを待っています。T12 が止まっていれば、先に T12 を片づけます。

## PC を再起動した・スリープした

PC にログインすると alpacawork は自動で起動し、タスクは元のまま残ります。再起動の前に動いていた作業は止まります。「対応待ち」に移ったタスクは、開いて「やり直す」を押します。自動では再開しません。

スリープ中は作業が進みません。ノート PC はふたを閉じると止まります。

## 画面が開かない

「このサイトにアクセスできません」と出るときは、alpacawork が動いていません。起動してから、ページを再読み込みします。

- Windows: スタートメニューから Ubuntu を開くと、alpacawork も起動します。ウィンドウは開いたままにします。それでも開かなければ、そのウィンドウで次の Linux のコマンドを実行します。
- Linux: `systemctl --user start alpacawork.service`
- macOS: `launchctl kickstart gui/$(id -u)/alpacawork.service`

URL を忘れたときは、ターミナルで `alpacawork workspace url` を実行します。

ほかの端末から `http://127.0.0.1:...` は開けません。[スマートフォンで使う](remote.md#スマートフォンで使う) か [SSH でつないだ PC](manage.md#ssh-でつないだ-pc-に入れたとき) の `https://` の URL を使います。

Node.js を更新したあとから起動しないときは、`alpacawork setup` を実行して Enter を押します。

## 「オフライン」などが出る

- 「オフラインになりました」「alpacawork の応答を待っています。」: alpacawork が動いているかを確かめます（上の「画面が開かない」）。つながると自動で戻ります。
- 「alpacawork の版が変わりました。」: 「再読み込み」を押します。
- 「端末の負荷が厳しい」: 「見る」で重い作業を確かめ、同時に動かす数を減らします。

## AI エージェントが使えない

「設定（歯車）→ サーバー」の「エージェント」に状態が出ます。

- 「サインインが必要」: 出ているコマンド（`claude auth login`、`codex login`、`gh auth login`）をターミナルで実行します。
- 「見つかりません」: 入れていなければ入れます。入れてあるなら、カードの「実行ファイル」で場所を指定します。
- 「有効な AI がありません」: 使う AI を有効にします。

直したあと、止まっていたタスクは「やり直す」で進めます。

## インストールで止まる

出た原因を直して、同じコマンドをもう一度実行すると、続きから進みます。

- `requires Node >=24.16.0`: Node.js 24 を入れてから実行します。
- `command not found`: ターミナルを開き直します。
- 書き込めないエラー、`does not run as root`: `sudo` を付けずに、nvm などで入れた Node.js で実行します。
- `User service manager is unavailable`: WSL2 なら [systemd を有効にします](manage.md#windows-で使うとき)。

ほかのメッセージは、出た文をそのまま AI に貼って相談します。

## AI に相談するときに渡すもの

ターミナルで Claude Code や Codex を起動し、alpacawork スキルを呼んでから（`/alpacawork` か `$alpacawork`）、次を渡します。

- 出た文をそのまま。タスクの番号（T12 など）
- 何をしたあとに起きたか
- `alpacawork workspace url` の出力

不具合は [Issues](https://github.com/alpacakit/alpacawork/issues) へ。脆弱性は Issue に書かず、[SECURITY.md](https://github.com/alpacakit/alpacawork/blob/main/SECURITY.md) の手順で知らせます。
