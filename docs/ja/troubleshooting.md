# 困ったとき

画面に出た言葉や、起きていることから、意味と次にすることを引くページです。ほかのページは [ドキュメントの入口](README.md) から引けます。

- [タスクが「対応待ち」にある](#タスクが対応待ちにある)
- [送ったのに進まない](#送ったのに進まない)
- [タスクが動いているか分からない](#タスクが動いているか分からない)
- [PC を再起動した・スリープしたあと](#pc-を再起動したスリープしたあと)
- [画面が開かないとき](#画面が開かないとき)
- [画面に接続の表示が出る](#画面に接続の表示が出る)
- [AI エージェントが使えない](#ai-エージェントが使えない)
- [インストール・セットアップで止まる](#インストールセットアップで止まる)
- [AI に相談するときに渡すもの](#ai-に相談するときに渡すもの)
- [不具合や脆弱性を知らせる](#不具合や脆弱性を知らせる)

使い方や直し方は、AI に聞くのが早道です。AI は alpacawork スキルから、設定・更新・復旧の手順を読めます。

- **画面が開けるとき**: 入力欄でそのまま聞きます。「予約フォームのタスクが進まないのはなぜ？」「Codex も使えるようにして」
- **画面が開けないとき**: [画面が開かないとき](#画面が開かないとき) を見てください。URL が分からないときは [画面を開き直す](manage.md#画面を開き直す) にあります。

データの置き場（`~/alpacawork`）や記録のファイルを、自分で消してやり直さないでください。データを失うことがあります。

スマートフォンと通知の困りごとは [スマートフォンでうまくいかないとき](remote.md#スマートフォンでうまくいかないとき)、更新は [更新が進まないとき](manage.md#更新が進まないとき)、アンインストールを断られたときは [断られたとき](manage.md#断られたとき) にあります。

## タスクが「対応待ち」にある

「対応待ち」は、AI の実行が止まっていて、あなたが決めるまで進まないタスクです。一覧の行に理由の言葉（「失敗」「上限停止」など）が出て、タスクを開くと、題の下に理由の文が出ます。行に出るそのほかの言葉（「途中で終了」「時間切れ」など）は [止まった理由の言葉](reference.md#止まった理由の言葉) にあります。

### 失敗

タスクを開くと「エージェントの実行が失敗したか、報告せずに終わりました。やり直すか止めるかを選んでください」と出ます。

| 押すもの | 起きること |
| --- | --- |
| 「やり直す」 | 窓口の AI（コーディネーター）に「T12 をやり直す」と送られ、窓口の AI が担当にやり直しを頼みます |
| 「止める」 | そのタスクと、下のタスクが中止になります。押すとすぐに中止になり、「取り消す」は出ません（[作業を止める](guide.md#作業を止める)） |

やり方を変えてほしいときは、ボタンを押す代わりに、タスクを開いたまま入力欄に書いて送ります。何度やり直しても失敗するときは、入力欄で「T12 が失敗する理由を調べて」のように聞きます。

### 利用上限に達した

AI エージェントの契約の利用上限に達して実行が失敗したときも、一覧の行は「失敗」です。タスクを開くと、次の文が出ます。

| 出る文 | すること |
| --- | --- |
| 「エージェントが週の利用上限に達し、実行が失敗しました。上限が戻ってからやり直すか、止めるかを選んでください」 | 上限が戻ってから「やり直す」を押します |
| 「モデルが混み合っていて（容量不足）、実行が失敗しました。時間をおくか別のモデルでやり直すか、止めるかを選んでください」 | 時間をおいて「やり直す」を押すか、別のモデルでやり直すよう頼みます |

- 上限が戻っても、自動では再開しません。戻ったあとで「やり直す」を押します。
- 別のモデルで進めるときは、タスクを開いたまま、入力欄に「別のモデルでやり直して」のように書いて送ります。
- 利用上限に達していても、上の文にならず、[失敗](#失敗) の文で出ることがあります。することは同じです。
- 「やり直す」を押したあとに「返事を受け取れませんでした」と出るときは、[送ったのに進まない](#送ったのに進まない) を見てください。

### 上限停止

AI の契約の利用上限とは別のものです（そちらは [利用上限に達した](#利用上限に達した)）。タスクを開くと「自動のやり取りが上限で止まりました（3 件）」のように出ます。人の指示なしに AI へ自動で届く依頼が、上限の回数（初めは20回）に達しています。かっこの中は、届かずに待っている件数です。

- 続けてよければ「続ける」を押します。窓口の AI に「T12 を続ける」と送られ、回数は数え直しになります。
- 上限の回数は、「設定（歯車）→ サーバー」の「高度なオプション」にある「1つのタスクで1エージェントへ自動で届く依頼の上限」で変えられます（[同時に動かす数と実行の上限](projects.md#同時に動かす数と実行の上限)）。

### そのほかの理由

次の理由には、ボタンがありません。タスクを開いたまま、入力欄に指示（「続けて」など）を書いて送ります。

| 行の言葉 | 出る文 | 意味と、すること |
| --- | --- | --- |
| 受領不明 | 「エージェントに返事が届いたか確認できません。結果を確かめ、必要なら指示を送ってください」 | 届いていないとは限りません。「履歴」で進み具合を確かめ、止まっていれば指示を送ります |
| 設定なし | 「エージェントの起動設定がありません。設定を確認して指示を送ってください」 | 担当の AI エージェントが、設定に無いか、有効になっていません。「設定（歯車）→ サーバー」で有効にしてから（[有効にする・デフォルトを決める](projects.md#有効にするデフォルトを決める)）、指示を送ります |
| 再開不可 | 「エージェントの前の会話は続けられません。新しい会話への指示を送ってください」 | 「新しい会話で続けて」のように指示を送ります |
| 開始不可 | 「責任者への依頼を始められません。責任者の有無と起動設定を確かめて、指示を送り直してください」 | タスクの担当（責任者）がいないか、その AI エージェントが設定にありません。「設定（歯車）→ サーバー」を確かめ、「担当を決めて進めて」のように指示を送ります |
| 深さ上限 | 「依頼が深さの上限に達しました。結果を確認し、必要なら新しい指示を送ってください」 | 子のタスクを重ねられる段数の上限（初めは8）に達しています。「履歴」を確かめ、続きが要れば指示を送ります |
| 依頼上限 | 「この実行の依頼数が上限に達しました。作業を確認し、必要なら別の指示を送ってください」 | 1回の実行が出せる依頼の数の上限（初めは200）に達しています。「履歴」を確かめ、続きが要れば指示を送ります |
| 受付拒否 | 「続きの依頼が受け付けられませんでした。理由を確認して新しい指示を送ってください」（代わりに、断られた理由の文が出ることもあります） | 理由を読み、直してから指示を送ります |

## 送ったのに進まない

送った文は入力欄から消え、入力欄の上に送信の状況が出ます。そこを押すと、コーディネーターとの会話が開きます。

| 見えるもの | 意味 | すること |
| --- | --- | --- |
| 「まもなく送信」「送信中…」「順番待ち」「コーディネーターを起動中です」「対応中です…」 | 送信の途中か、窓口の AI が動いています | 待ちます。「まもなく送信」「順番待ち」の間は、「取り消す」で送信をやめられます |
| 「エージェントが受け取れなかったため、列で待っています。」 | 送った文が、順番を待っています | 待ちます |
| 「送れませんでした（理由）。入力欄に戻しました。」 | 受け付けられず、文は入力欄に戻っています | 理由を読んで直し、もう一度送ります |
| 会話の中の「送れませんでした（理由）」 | 受け付けられず、文は会話に残っています | 「入力に戻す」を押し、直して送ります。入力欄に書きかけがあると押せないので、先に入力欄を空にします |
| 「届いたか分かりません。会話で送り直すか取り消してください。」「届いたか分かりません。」 | 届いたかどうかを確かめられていません | 会話を開き、「送り直す」か「取り消す」を押します |
| 「返事を受け取れませんでした：（理由）」 | 窓口の AI の実行が失敗しました。下に、AI エージェントが出したエラーの文が出ることがあります | 「送り直す」を押します。理由ごとのことは下の表にあります |
| 「コーディネーターの起動に失敗しました。」 | 窓口の AI の準備ができませんでした | [AI エージェントが使えない](#ai-エージェントが使えない) を確かめます |

| 「返事を受け取れませんでした」の理由 | すること |
| --- | --- |
| 「エージェントを起動できませんでした」 | [AI エージェントが使えない](#ai-エージェントが使えない) を確かめてから「送り直す」を押します |
| 「週の利用上限に達しました」「モデルが混み合っています（容量不足）」 | 上限が戻ってから「送り直す」を押します。または、送信ボタンの横で別のモデルを選んで、もう一度送ります |
| 「時間切れで停止しました」 | 窓口の AI の1回の実行の上限（初めは30分）を超えました。「送り直す」を押します |
| 「エージェントが途中で終了しました」「途中で停止しました」など | 「送り直す」を押します。繰り返すときは [AI に相談するときに渡すもの](#ai-に相談するときに渡すもの) の手順で相談します |

返事の冒頭が出ているのに一覧にタスクが出ないときは、会話を開いて、窓口の AI の返事を読みます。

## タスクが動いているか分からない

一覧の行と、開いたタスクの「履歴」で確かめます。分からないときは、入力欄で「予約フォームのタスクが進まないのはなぜ？」のように聞きます。

| 見えるもの | 意味 | すること |
| --- | --- | --- |
| 「作業中」の行の時間が増えていく | AI が動いています。時間は、AI が動いた時間の合計です | 待ちます。タスクを開くと、「履歴」の上に、動いている AI と最新の動きが出ます |
| 開いたタスクの「最後の出力が古い: …（12分前）」 | AI の出力が10分以上ありません。止まったとは限りません | しばらく待ち、変わらなければ入力欄で聞きます |
| 行の「順番待ち」 | AI の実行が、空きを待っています。同時に動かす数の上限（初めは8）に達しているときなどです | 待ちます。数は [同時に動かす数と実行の上限](projects.md#同時に動かす数と実行の上限) で変えられます |
| 行の「T12 待ち」 | T12 が終わるのを待っています | タスクを開いて「依存」を見ます。「T12 はエラーで止まっています。直して完了するか中止し、実行が終わると、待ちが解けます。」と出るときは、先に T12 を片づけます（[タスクが「対応待ち」にある](#タスクが対応待ちにある)） |
| 行の「状態不明」「実行を確認できず」 | AI の実行がどうなったかを、alpacawork が確かめられていません | しばらく待ち、変わらなければ入力欄で聞きます |
| 「待機中」にある | 子のタスクやほかの返事を待っていて、そのタスクで動いている AI はいません | 開いて「タスクツリー」と「依存」で、待っている相手を確かめます |

## PC を再起動した・スリープしたあと

PC を再起動したあとは、PC にログインすると alpacawork が自動で起動します（Windows では、スタートメニューから Ubuntu を開くと起動します）。タスクは元のまま残っています。インストールをやり直す必要はありません。

ブラウザで画面が開かないときは、先に [画面が開かないとき](#画面が開かないとき) の手順で alpacawork を起動します。

再起動する前に動いていた AI の作業は、再起動で止まります。画面が開いたら、一覧を確かめます。

| 見えるもの | すること |
| --- | --- |
| 「対応待ち」にタスクがある | 開いて「やり直す」を押します（[失敗](#失敗)）。対応待ちのタスクは、自動では再開しません |
| 行に「状態不明」「実行を確認できず」と出ている | しばらく待ちます。変わらなければ入力欄で聞きます |
| 「作業中」「待機中」のまま進まない | [タスクが動いているか分からない](#タスクが動いているか分からない) |

- **スリープ**: AI は PC の上で動くので、スリープしている間は作業が進みません。長く動かすときは、PC をスリープしない設定にします（ノート PC は、ふたを閉じると止まります）。スリープから戻ったあとも、上の表で確かめます。
- **Windows**: Ubuntu のウィンドウをすべて閉じたときも、Ubuntu が止まって、alpacawork と作業中の AI が一緒に止まることがあります。Ubuntu を開き直して、上の表で確かめます（[Windows で使うとき](manage.md#windows-で使うとき)）。

## 画面が開かないとき

URL が分からないときは、先に [画面を開き直す](manage.md#画面を開き直す) を見てください。

ブラウザに「このサイトにアクセスできません」や `ERR_CONNECTION_REFUSED` のように出てつながらないときや、`alpacawork workspace url` が「Server not reached」で失敗するときは、alpacawork が動いていません。

alpacawork は、PC にログインすると自動で起動します（Windows では、Ubuntu を開くと起動します）。動いていないときは、下の手順で起動してから、ページを再読み込みします。

- **Windows**: スタートメニューから Ubuntu を開き、そのウィンドウを開いたままにします（[Windows で使うとき](manage.md#windows-で使うとき)）。それでも開かないときは、そのウィンドウで下の Linux のコマンドを実行します。
- **Linux**: ターミナルで `systemctl --user start alpacawork.service` を実行します。alpacawork は PC にログインしている間動きます。
- **macOS**: ターミナルで `launchctl kickstart gui/$(id -u)/alpacawork.service` を実行します。[alpacawork を止める・起動する](manage.md#alpacawork-を止める起動する) の手順で止めたときは、代わりに `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/alpacawork.service.plist` を実行します。

止める・再起動するコマンドと、Linux でログアウトしたあとも動かしておく方法は、[alpacawork を止める・起動する](manage.md#alpacawork-を止める起動する) にあります。起動しても開かないときは、次を確かめます。

| 起きていること | すること |
| --- | --- |
| Node.js を更新したあとから、起動しなくなった | alpacawork は、セットアップしたときの Node.js で起動します。更新で Node.js の場所が変わると、起動できません（Homebrew の `node` は、更新のたびに変わります）。ターミナルで `alpacawork setup` を実行し、変わるところ（「Node.js」の行）を確かめて Enter を押します |
| 「このブラウザには対応していません」と出る | ブラウザが古すぎます。Chrome・Edge 111、Safari 16.4、Firefox 128 以降で開きます。iPhone・iPad は、iOS／iPadOS 16.4 以降に更新します |
| ほかの PC やスマートフォンから開けない | `http://127.0.0.1:...` の URL は、alpacawork を入れた PC でしか開けません。ほかの端末からは、VPN を通る `https://` の URL で開きます（[スマートフォンで使う](remote.md#スマートフォンで使う)）。PC の IP アドレスや `http://` の URL では開けません |

それでも開かないときは、[AI に相談するときに渡すもの](#ai-に相談するときに渡すもの) の手順で、AI に相談します。

## 画面に接続の表示が出る

画面は開いているのに、次の表示が出るときです。

| 見えるもの | 意味 | すること |
| --- | --- | --- |
| 「オフラインになりました。接続が戻るまで、送信や変更はできません」、上のバーの「オフライン」の印（押すと「オフラインです」） | 画面が alpacawork につながっていません。前に読み込んだ内容が出ています | alpacawork が動いているかを確かめます（[画面が開かないとき](#画面が開かないとき)）。スマートフォンでは、VPN がつながっているかも確かめます。つながると、表示は自動で消えます。すぐ試すときは「再接続」を押します |
| 「サーバーに接続できません。5秒後にもう一度つなぎます」（「設定（歯車）→ サーバー」の「読み取りと接続の状況…」の中） | 上と同じです | 上と同じです。つなぎ直しは自動で続きます |
| 「alpacawork の応答を待っています。」「応答があると、自動で元の画面に戻ります。」 | 画面を開いたときに、alpacawork が応答しませんでした | alpacawork を起動します（[画面が開かないとき](#画面が開かないとき)）。応答があると、自動で戻ります |
| 「alpacawork の版が変わりました。」「再読み込みすると、元の画面に戻ります。」 | alpacawork が更新され、開いている画面が前の版のままです | 「再読み込み」を押します。版が変わらないときは、開いている画面をすべて閉じて、開き直します |
| 「config.yaml を読み取れません」「書き込めません」 | 設定のファイル（データの置き場の `config.yaml`）を読めません。直るまで、新しい AI の実行は始まらず、画面からの送信や変更もできません。動いている実行は、終わりまで進みます | 「状況を見る」を押すか、「設定（歯車）→ サーバー」で理由を読みます。ファイルを直すと、再起動しなくても動き出します。直し方が分からないときは、ターミナルの AI に頼みます（[AI に相談するときに渡すもの](#ai-に相談するときに渡すもの)） |
| 「端末の負荷が厳しい」「CPU 98% · 12分」 | PC の CPU の使用率（90% 以上が2分）、メモリの空き（10% 未満が1分）、ディスクの空き（50 GB 未満）のどれかが厳しくなっています。Linux と WSL2 で出ます | 「見る」を押すと、「端末の状態」で重い作業が分かります。同時に動かす数を減らすか（[同時に動かす数と実行の上限](projects.md#同時に動かす数と実行の上限)）、ディスクの空きを増やします |

## AI エージェントが使えない

「設定（歯車）→ サーバー」の「エージェント」と、セットアップの最初のステップに、AI エージェントごとの状態が出ます。コマンドは、ターミナル（Windows では Ubuntu のウィンドウ）で実行します。

| 見えるもの | 意味 | すること |
| --- | --- | --- |
| 「サインインが必要」、「サインインしていません。端末で `claude auth login`」 | その AI エージェントにサインインしていません | 表示されたコマンドを実行して、サインインします。Claude Code は `claude auth login`、Codex は `codex login`、GitHub Copilot は `gh auth login` です。セットアップの画面では、そのあと「もう一度確認」を押します |
| 「claude コマンドが見つかりません。インストールすると使えます」、「実行ファイルが見つかりません: claude」 | 入っていないか、alpacawork が探す場所にありません | 入れていなければ、入れます。入れてあるのに出るときは、場所を指定します（[実行ファイルの場所を指定する](projects.md#実行ファイルの場所を指定する)） |
| 「いま使えるエージェントがありません」（セットアップの画面） | 入れてあってサインイン済みの AI エージェントが、1つもありません | 1つ以上にサインインして「もう一度確認」を押します。あとで設定するときは「エージェントなしで進む」を押します |
| 送ったあとの「有効な AI がありません。使う AI をインストールして認証し、設定 → サーバーで有効にしてください」 | 有効にしてある AI エージェントが、1つもありません | 「設定（歯車）→ サーバー」で、使うものを有効にします（[有効にする・デフォルトを決める](projects.md#有効にするデフォルトを決める)） |
| 「インストール済み。サインインか API キーの設定が済んでいれば使えます」（Grok Build、pi） | サインインの状態を alpacawork が確かめられない種類です。初めは無効になっています | サインインか API キーの設定を済ませ、自分で有効にします（[使える AI エージェント](projects.md#使える-ai-エージェント)） |
| 「認証が必要です。…」、「環境変数ファイルを読み込んでいません」 | API キーで動かす AI エージェントに、キーが渡っていません | [API キーを渡す](projects.md#api-キーを渡す) の手順で、キーをファイルに書きます |

サインインや設定を直したあと、止まっていたタスクは「やり直す」で進めます（[失敗](#失敗)）。

## インストール・セットアップで止まる

途中で止まったときは、出た原因を直してから、同じコマンドをもう一度実行します。続きから進みます。設置の記録やデータを消して、最初からやり直さないでください。英語のメッセージは、ターミナルのエラーの行の中に、下の形で出ます。

| メッセージ | 原因 | すること |
| --- | --- | --- |
| `alpacawork requires Node >=24.16.0; install Node separately` | Node.js が 24.16 より古い | Node.js 24 を入れてから、もう一度実行します。AI に「Node.js 24 を入れて alpacawork をインストールして」と頼めます |
| `This package has no runtime closure for ...` | 対応していない PC です（Intel の Mac、ARM の Linux など） | 使えるのは、macOS（Apple シリコン）、Linux（x64、glibc）、Windows（WSL2）です |
| `command not found`（`alpacawork`、`node`、`npm`） | Node.js を入れた直後で、ターミナルがまだコマンドを見つけられません。または、Node.js 24 が選ばれていません | ターミナルを開き直します。Node.js をいくつか入れているときは、24 を選んだターミナルで実行します |
| `npm install -g alpacawork` が、書き込めないというエラーで失敗する | Node.js が PC 全体に入っていて、`sudo` なしでは書き込めません | `sudo` は付けません。nvm などで Node.js 24 を入れてから、もう一度実行します |
| `alpacawork does not run as root. ...`、`Initialize as the intended user without sudo` | root として、または `sudo` を付けて実行しました。何も変わっていません | ふだん使うユーザーで、`sudo` を付けずに実行します |
| `User service manager is unavailable. ...` | 自動起動に使う systemd のユーザーセッションがありません。WSL2 で systemd が無効なときなどです | WSL2 では、下の手順で systemd を有効にします |
| 「WSL2 のデータ・アプリの保存先・設定は Linux 側に置いてください。/mnt/c など Windows 側のフォルダは使えません。」 | データなどの保存先が、Windows 側のフォルダ（`/mnt/c` など）になっています | `--workspace` などを付けずに、`cd ~` を実行してから `alpacawork setup` を実行します |
| `Default workspace path is not empty: ...` | `~/alpacawork` に、alpacawork のものではないファイルがあります。何も変わっていません | 空のフォルダを決めて、`alpacawork setup --workspace <フォルダ>` を実行します。データの置き場は、あとから変えられません |
| 「自動起動できませんでした。次のコマンドで状態とログを調べてください。」 | サーバーを自動で起動できませんでした | 続けて出るコマンドを実行して、原因を読みます。直したら、同じ `alpacawork setup` をもう一度実行します。分からないときは、出力を AI に貼って相談します |
| セットアップの画面の2つ目のステップの「インストールできませんでした。…」 | スキルを取得できませんでした（npm が動かない、GitHub につながらない、時間切れ、`~/.claude/skills` に同じ名前の別のものがある） | インストールのボタンをもう一度押すか、「スキップ」で先へ進みます。スキルは、あとから入力欄で「askmeclearly を入れて」のように頼んで入れられます |

WSL2 で systemd を有効にする手順（Ubuntu で `ps -p 1 -o comm=` を実行して `systemd` と出れば、有効です）:

1. Ubuntu で、`/etc/wsl.conf` に `[boot]` と `systemd=true` の2行を、この順に足します（`sudo` が要ります）。
2. PowerShell で `wsl --shutdown` を実行し、Ubuntu を開き直します。
3. もう一度 `alpacawork setup` を実行します。

## AI に相談するときに渡すもの

画面が開けないときは、ターミナルで AI エージェント（Claude Code や Codex など）を起動し、alpacawork スキルを呼んで（[呼び方](remote.md#いつもの-claude-codecodex-から使う)）、表示されたエラーを貼って相談します。次のものを渡すと、原因を調べやすくなります。

- 画面やターミナルに出た文。言い換えずに、そのまま貼ります。タスクのことなら、タスクの番号（T12 など）も添えます
- 何をしたあとに起きたか（更新した、PC を再起動した、Node.js を更新した、など）
- 次のコマンドの出力（alpacawork が動いているかと、サーバーの記録）

Linux・WSL2:

```sh
alpacawork workspace url
systemctl --user status alpacawork.service
journalctl --user -u alpacawork.service -n 50 --no-pager
```

macOS:

```sh
alpacawork workspace url
launchctl print gui/$(id -u)/alpacawork.service
log show --last 10m --style compact --predicate 'process == "launchd" AND eventMessage CONTAINS "alpacawork.service"'
```

macOS には、サーバーの出力を残すファイルがありません。上のコマンドで分かるのは、状態と、起動の記録です。セットアップが途中で止まったときの記録は、`~/.local/state/alpacawork/setup.log` にあります。

## 不具合や脆弱性を知らせる

不具合は、[Issues](https://github.com/alpacakit/alpacawork/issues) に書きます。貼るログや画像に、タスクの中身や秘密が入っていないかを確かめてから書きます。

脆弱性を見つけたときは、公開の Issue に書かず、[SECURITY.md](https://github.com/alpacakit/alpacawork/blob/main/SECURITY.md) の手順で知らせてください（英語です）。
