## 画面を開き直す

alpacawork の画面は、PC で動いている alpacawork が出している Web ページで、ブラウザで開きます。URL は `http://127.0.0.1:43127/` のような形です（`127.0.0.1` の代わりに `localhost` でも開けます）。最後の数字はインストールのときに決まるので PC ごとに違い、ブラウザを閉じても、PC を再起動しても変わりません。

- **ブラウザを閉じたあとや、PC を再起動したあと**も、同じ URL で開きます。再起動したときは、先に PC にログインします（Windows では Ubuntu を開きます）。
- **ブックマークするか、アプリとして入れます。** Chrome や Edge では、アドレス欄の右端の「インストール」を押します（Edge では同じ場所のアイコン）。入れると、Dock やタスクバー、アプリの一覧から、専用のウィンドウで開けます。ブラウザごとの手順は、画面の「設定（歯車）→ アプリ・スマホ → デスクトップアプリとして使う」にあります。
- **URL を忘れたときは**、ターミナル（Windows では Ubuntu のウィンドウ）で `alpacawork workspace url` を実行します。alpacawork が動いていれば `"status":"serving"` と出ます。その PC のブラウザでは `"localUrl"` のあとの URL を開きます。ほかの端末からは `"publicUrl"` のあとの URL を開きます。ほかの端末から使う設定をするまでは `null` です（[スマートフォンで使う](remote.md#スマートフォンで使う)）。Claude Code や Codex などの AI エージェントに「alpacawork の URL を教えて」と頼んでも分かります。

URL を開いてもつながらないときは、[画面が開かないとき](troubleshooting.md#画面が開かないとき) を見てください。

## Windows で使うとき

Windows では、alpacawork も、Node.js も、AI エージェントも、WSL2（Windows の中で Linux を動かす仕組み）の Ubuntu の中に入れます。インストールの指示文（[インストールする](getting-started.md#1-インストールする)）も、Ubuntu の中で起動した AI エージェントに貼り付けます。

WSL2 や Ubuntu がまだ無いときは、Windows で動いている AI エージェントに同じ指示文を貼り付けると、その準備から案内します。自分で入れるときは、管理者として開いた PowerShell で `wsl --install` を実行します（[Microsoft の手順](https://learn.microsoft.com/ja-jp/windows/wsl/install)）。

alpacawork は Ubuntu の中で動き、画面は Windows のブラウザで開きます。動くのは、Ubuntu が動いている間だけです。

- **使っている間は、Ubuntu のウィンドウを1つ開いたままにします。** スマートフォンから使っている間も同じです。すべて閉じると Ubuntu が止まることがあり、alpacawork も、作業中の AI も一緒に止まります。
- **Windows を再起動したあとは、スタートメニューから Ubuntu を開きます。** Ubuntu を開くと alpacawork は自動で起動し、タスクは元のまま残っています。インストールをやり直す必要はありません。

## SSH でつないだ PC に入れたとき

SSH でつないだ別の PC に入れたときは、その URL は、その PC のブラウザでしか開けません。SSH の中で、その PC の AI エージェントに「alpacawork をほかの端末から使えるようにして」と頼みます。AI が VPN を通る入口を用意し、手元の端末に入れるものを伝えます（[スマートフォンで使う](remote.md#スマートフォンで使う) に説明があります）。伝えられた `https://` の URL を、手元のブラウザで開きます。

## alpacawork を止める・起動する

alpacawork は、PC にログインすると自動で起動します（Windows では、Ubuntu を開くと起動します）。自分で止める・起動するときは、ターミナル（Windows では Ubuntu のウィンドウ）で次を実行します。

| すること | Linux・WSL2 | macOS |
| --- | --- | --- |
| 止める | `systemctl --user stop alpacawork.service` | `launchctl bootout gui/$(id -u)/alpacawork.service` |
| 起動する | `systemctl --user start alpacawork.service` | 上の「止める」で止めたあとは `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/alpacawork.service.plist`。それ以外は `launchctl kickstart gui/$(id -u)/alpacawork.service` |
| 再起動する | `systemctl --user restart alpacawork.service` | `launchctl kickstart -k gui/$(id -u)/alpacawork.service`（止めてあるときは、上の「起動する」） |
| 動いているか見る | `systemctl --user status alpacawork.service` | `launchctl print gui/$(id -u)/alpacawork.service` |

- 止めたあとは、次に PC にログインしたとき（Windows では、Ubuntu を開いたとき）か、上の「起動する」で、また動きます。
- サーバーを止めても、動いている AI の作業は止まりません。作業を止めたいときは、先に [作業を止める](guide.md#作業を止める) の「中止」をします。
- API キーを書くファイルを書き換えたあとは、再起動します（[API キーを渡す](projects.md#api-キーを渡す)）。画面の設定を変えたあとは、再起動は要りません。
- Linux では、alpacawork は PC にログインしている間動きます。ログアウトしたあとも動かしておくときは、AI エージェントに「ログアウトしても alpacawork が動き続けるようにして」と頼みます。

起動しても画面が開かないときは、[画面が開かないとき](troubleshooting.md#画面が開かないとき) を見てください。

## 更新する

新しい版が出ると、画面の設定（歯車）に印が付きます。作業中の AI がいても始められます（AI が止まってからでないと入れられない版は、[更新のボタンが出ないとき](#更新のボタンが出ないとき)）。

1. 設定（歯車）を開きます。タブの上に、新しい版と今の版が「… があります（今は …）」と出ます。横の「変更点」で、その版の変更点を読めます。
2. 「アップデート」を押します。確認の画面に、次のことが出ます。
   - 切り替えのあいだ、画面はしばらく使えません。作業中の AI は止まらずに続きます。
   - 更新したあとは、前の版に戻せません。
   - スキル（alpacawork など）は新しい版の内容で上書きされ、手で書き換えた内容は消えます。
3. 確認の画面の「アップデート」を押します。切り替えが終わると、画面が戻ります。
4. 「新しい版になりました。再読み込みで切り替わります。…」と出たら、「再読み込み」を押します。

確認の画面の「次回もこの確認を表示する」を外すと、次からは確認の画面が出ません。今の版は、設定のいちばん下に `alpacawork 0.1.5` のように出ています。

### 更新のボタンが出ないとき

**歯車に印が出ていないとき**: 新しい版があるかは、alpacawork が動いている間に自動で確かめます。印が出る前に入れたいときは、[画面を使わずに更新する](#画面を使わずに更新する) のコマンドを実行します。

**「アップデート」の代わりに文が出ているとき**: 作業中の AI がいる間は入れられない版があります。そのときは「アップデート」の代わりに、「…は、作業中のエージェント（…件）が止まってから入れられます。…」という文と、「止める指示をコピー」が出ます。

1. 「止める指示をコピー」を押し、入力欄に貼り付けて送ります。窓口の AI（コーディネーター）が、作業中のタスクを保留にして、切りの良いところで止めます。
2. 作業中の AI がいなくなると「アップデート」が出るので、上の手順で更新します。
3. 更新が終わったら、入力欄で「止めていた作業を再開して」のように頼みます。

### 更新が進まないとき

設定を開くと、タブの上に今の状況が1行で出ます。

| 出る文 | ボタン | すること |
| --- | --- | --- |
| 「作業中のエージェント…件が終わるのを待っています」 | 「延期する」 | AI の作業が終わると、切り替わります。今回はやめるときは「延期する」を押します。今の版のまま使え、あとでまた更新できます |
| 「…には、作業中のエージェント（…件）が終わるまで切り替えられません。今の版のまま使えます。…」 | 「再試行」 | 「止める指示をコピー」で止める指示を送り（[更新のボタンが出ないとき](#更新のボタンが出ないとき)）、AI が止まってから「再試行」を押します |
| 「…をダウンロードできませんでした。…」 | 「再試行」 | PC のインターネット接続を確かめてから、「再試行」を押します |
| 「この PC のディスクの空きが足りず、…を入れられませんでした。…」 | 「再試行」 | ディスクの空きを作ってから、「再試行」を押します |
| 「…を入れられませんでした。今の版のまま使えます」 | 「再試行」 | 「再試行」を押します |
| 「…への切り替えが止まっています。続けると、止まったところから進めます」 | 「続ける」 | 「続ける」を押します |
| 「…は取り下げられました」 | なし | 配布元が取り下げた版で、入りません。することはありません |

- **「再読み込み」を押しても版が変わらないとき**: 開いている alpacawork の画面をすべて閉じて、開き直します。
- **「再試行」や「続ける」でも進まないとき**: ターミナルで、同じ版を指定して [画面を使わずに更新する](#画面を使わずに更新する) のコマンドを実行します。止まったところから続きます。それでも進まないときは、AI に相談します（[AI に相談するときに渡すもの](troubleshooting.md#ai-に相談するときに渡すもの)）。データや更新の記録のファイルを、自分で消してやり直さないでください。

### 画面を使わずに更新する

ターミナル（Windows では Ubuntu のウィンドウ）で、入れる版を指定して次を実行します。`@<版>` を省くと、最新の版になります。

```sh
alpacawork deploy npm:alpacawork@<版>
```

今の版と入れる版が表示され、`続行しますか？ [Y/n]` と聞かれるので、確かめてから Enter を押します。作業中の AI がいる間は入れられない版では、AI の作業がすべて終わってから実行します。終わったら、開いている画面を再読み込みします。

- `npm install -g alpacawork` だけでは、動いている alpacawork は新しい版になりません。
- 更新に `alpacawork setup` は使いません。インストール済みの PC で、ポートなどの設定を変えずに実行すると、動いている版が npm で入れてある版と違うときに、npm で入れてある版へ切り替わります。それが古い版なら、古い版に戻ります。

## アンインストールする

AI エージェント（Claude Code や Codex など）に、「alpacawork をアンインストールして」と頼みます。自分で行うときは、ターミナルで次の2行を順に実行します。

```sh
alpacawork uninstall
npm uninstall -g alpacawork
```

1行目は、消すものと残すものを表示します。読んでから Enter を押します。AI が作業している間は、アンインストールできません。2行目は、1行目が終わってから実行します。1行目を断られたまま2行目を実行すると、`alpacawork uninstall` をやり直せなくなります。

### 消えるもの・残るもの

消えるものは、元に戻せません。

- **自動起動の登録**: サーバーを止めてから外します
- **alpacawork のプログラム**: `~/.local/share/alpacawork/releases` のうち、alpacawork が置いたもの
- **設定と設置の記録**（`~/.config/alpacawork/`）: API キーを書いたファイル（`env`）と、使用統計データを送るかどうかの選択も、この中にあり、一緒に消えます
- **状態のフォルダ**（`~/.local/state/alpacawork`）
- **alpacawork が管理しているスキル**（alpacawork、alpacawork-betterquality など）と、Claude Code から使うためのリンク: 手で直した内容も消えます

残るものは、次のとおりです。

- **データの置き場**（`~/alpacawork`。タスクと記録）: 要らなければ、自分で消します
- **ほかの方法で入ったスキル**（askmeclearly、doyourjob など）
- **Codex の会話の履歴と記憶**（`~/.codex-alpacawork`）
- **`alpacawork` コマンド本体**: 2行目の `npm uninstall -g alpacawork` で消えます

### 断られたとき

出た文に合わせて対応し、もう一度 `alpacawork uninstall` を実行します。

| 出る文 | すること |
| --- | --- |
| 「エージェントか更新がまだ動いています（…）。…」 | AI の作業か更新が動いています。作業を止めるか（[作業を止める](guide.md#作業を止める)）、終わるのを待ちます |
| 「更新などの操作が進行中です。…」 | 更新などが終わるのを待ちます |
| 「alpacawork uninstall は、この PC の本人だけが実行できます。エージェントからは実行できません。」 | alpacawork が起動した AI からは実行できません。ターミナルで自分で実行するか、ターミナルで起動した Claude Code や Codex に頼みます |
| 「sudo を付けずに、使っている本人として実行してください。」 | `sudo` を付けずに実行します |
| 「端末から打ち直すか、--yes を付けて確認なしで進めてください。」 | ターミナルで実行するか、`alpacawork uninstall --yes` を実行します |
| 「止めました。何も変えていません。」 | Enter 以外のキーを押したときに出ます。もう一度実行して、Enter を押します |
| 「サービス管理（launchd / systemd --user）に届かないため、…」 | PC にログインして開いたターミナル（Windows では Ubuntu のウィンドウ）で実行します |
| 「…何も変えていません。手で外すには次を実行してください…」 | 自動起動の登録を外せなかったときに出ます。表示されたコマンドを実行します |
| 「… で止まりました: …」 | 途中で止まっています。表示された原因を直して、もう一度実行すると、残りを消します |

### 入れ直す

アンインストールのあとに、もう一度インストールすると（[インストールする](getting-started.md#1-インストールする)）、残っているデータの置き場がそのまま使われ、タスクと記録は元のまま残っています。`alpacawork setup` が表示する一覧の「データ」の行に「（既存）」と出ます。

- **前と同じ URL で開く**: URL の最後の数字（ポート）は、入れ直すと選び直されます。前と同じにするには、前の数字を付けて `alpacawork setup --port 43127` のように実行します。ほかの端末から開く名前を設定していたときは、`--public-host <前の名前>` も付けます。
- **データの置き場が `~/alpacawork` でなかったとき**: `--workspace <その場所>` を付けます。
- **API キー**: 書いてあったファイルは消えているので、書き直します（[API キーを渡す](projects.md#api-キーを渡す)）。
- **使用統計データ**: 送るかどうかを選び直します（[使用統計データ](telemetry.md)）。

## 保存されるもの・外へ送られるもの

タスクや会話の中身が、開発元に送られることはありません。AI の提供元との通信は、Claude Code や Codex などを直接使うときと同じです。

| 何が | どこへ |
| --- | --- |
| タスクの内容、やり取り、成果のファイル、AI の出力 | あなたの PC のデータの置き場（既定は `~/alpacawork`）。AI が作業中に読んだ秘密が、出力に残ることがあります。このフォルダを人に渡さないでください |
| AI への指示と、AI が読んだ内容 | お使いの AI の提供元（Anthropic、OpenAI など） |
| 新しい版があるかの確認と、更新のダウンロード | npm（alpacawork の配布元）。サーバーが動いている間、自動で確かめます |
| スマートフォンへの通知（タスクの番号と題名、報告の題） | ブラウザの通知サービス（Google、Apple など）を、暗号化されて通ります |
| 使用統計データ（送信を選んだ場合だけ） | 開発元。会話やタスクの中身、ファイル、名前は含みません（[使用統計データ](telemetry.md)） |

API キーなどの秘密を、入力欄、プロジェクト方針、設定の起動オプションに書かないでください。書いた内容は記録に残ります。タスクを削除してもファイルは残るので、削除は秘密を消す手段になりません。

### データの場所

タスクと記録は、データの置き場（既定は `~/alpacawork`）にあります。今の場所は、設定（歯車）→ サーバー の下のほうの「読み込んでいるフォルダ」に出ます。インストールのあとで、場所は変えられません。

| 場所 | 入っているもの |
| --- | --- |
| `~/alpacawork` | タスクのファイル（`tasks/`）、サーバーの設定（`config.yaml`）、タスクと作業の記録（`.alpacawork/`）。`.alpacawork/` を手で消したり書き換えたりしないでください |
| `~/.config/alpacawork/` | 設置の記録、API キーを書くファイル（`env`）、使用統計データを送るかどうかの選択 |
| `~/.local/share/alpacawork/releases` | alpacawork のプログラムと、更新の記録 |
| `~/.agents/skills` | スキル。Claude Code からは `~/.claude/skills` のリンクで使います |
| `~/.codex-alpacawork` | alpacawork から動かした Codex の、会話の履歴と記憶 |

### 控えを取る

控えを取るコマンドはありません。次の手順で、フォルダごとコピーします。

1. AI が作業していないときに、alpacawork を止めます（[alpacawork を止める・起動する](#alpacawork-を止める起動する)）。
2. データの置き場を、権限を保ったまま丸ごとコピーします。例: `cp -a ~/alpacawork <コピー先>`
3. alpacawork を起動します。

動いている間に、中のファイルを一部だけコピーしないでください。手で取った控えから元に戻す手順は、用意されていません。控えにも秘密が入っているので、人に渡さないでください。

## AI エージェント向け

ここから下は、AI がこのドキュメントを読んで作業するときの案内です。人は読まなくてかまいません。

利用者にこのドキュメントにある作業を頼まれたら、下の表の手順書を、要約せずに読んで進めてください。手順書へのリンクは、このページからの相対パスです。インストール後は、同じものが `~/.agents/skills/alpacawork/` にもあります。手順書にある作業は、利用者の依頼の範囲です。自分で進め、利用者に聞くのは、手順書が聞くと定めていることだけにします。

| 作業 | 読む手順書と、守ること |
| --- | --- |
| インストール | [セットアップの手順書](../../skills/alpacawork/references/setup.md#install) の「Install」を全文読み、その順に進めます。最初に、すでに入っていないかを確かめます。`alpacawork setup --yes` は自分で実行し、利用者にコマンドを渡したり、手順ごとに承認を求めたりしません。利用者にしかできないことは、手順書の1か所にまとめてあります |
| プロジェクトを作るよう頼まれたとき | 最初のプロジェクトのフォルダ・方針・スキルはセットアップの画面で決めるので、インストールの直後には聞きません。プロジェクトを作るよう頼まれたら、[What to ask first](../../skills/alpacawork/references/setup.md#what-to-ask-first) に沿って、作業するフォルダなど、まだ決まっていないことを1つずつ聞き、答えを、その表にある保存先に書きます |
| アドオンを入れる | `alpacawork skills update` で入ります。本体と alpacawork-betterquality が入るので、更新の承認範囲を確認します。導入済みの非公開アドオンはそのまま残ります。担当の AI が使うのは、プロジェクト方針に書いたものだけです。書き方は [Sync the skills](../../skills/alpacawork/references/setup.md#sync-the-skills) と [What to ask first](../../skills/alpacawork/references/setup.md#what-to-ask-first) にあります |
| あとからスマートフォンで使えるようにする | [Connect](../../skills/alpacawork/references/setup.md#connect) と [Change the installation](../../skills/alpacawork/references/setup.md#change-the-installation) を読みます。要るのは、端末から PC への経路（VPN）、HTTPS の入口（例: `tailscale serve`）、その入口の名前を伝える `--public-host` の3つです。`--public-host` は、`alpacawork setup --yes --public-host <名前>` を実行して設定します。インターネットに公開する設定はしません |
| alpacawork スキルを呼ばれた会話 | `~/.agents/skills/alpacawork/SKILL.md` を読み、窓口（コーディネーター）として動きます。alpacawork が入れたスキルを Claude Code から使うには、`~/.claude/skills` にリンクが要ります。`/alpacawork` が出ないときは、[Sync the skills](../../skills/alpacawork/references/setup.md#sync-the-skills) を読み、リンクがあるかを確かめます |
| 更新、アンインストール | 外に影響する操作です。アンインストールは、利用者に頼まれたときだけ、`alpacawork uninstall --yes` で行います。更新は、実行する前に、プロジェクト方針、そこに定めがなければ適用される `AGENTS.md` の順で承認の範囲を確かめ、承認が要る場合と定めが無い場合は、利用者の承認を得ます。手順と、断られる条件は [Update](../../skills/alpacawork/references/setup.md#update) と [Uninstall](../../skills/alpacawork/references/setup.md#uninstall) にあります |
| タスクが進まない、サーバーが起動しない、更新が途中で止まった | [Troubleshooting](../../skills/alpacawork/references/troubleshoot.md) を読みます。設置の記録やデータを消して、最初からやり直しません |
