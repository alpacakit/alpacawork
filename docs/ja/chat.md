# Claude Code・Codex から使う

alpacawork は、画面の入力欄のほかに、ターミナルやアプリで開いた Claude Code・Codex の会話からも操作できます。

## 始めかた

会話の最初に、`/alpacawork` を付けて1回頼みます（Codex では `$alpacawork`）。

```text
/alpacawork 確認待ちのタスクを1件ずつ短く教えて
```

AI が alpacawork のスキルを読み、それからはその会話の AI が、画面の入力欄と同じ窓口の AI（コーディネーター）として動きます。2回目からは `/alpacawork` を付けずに頼めます。`/alpacawork` は、この会話にスキルを読ませるためのものです。alpacawork の画面の入力欄では付けません。

頼んだ作業は、alpacawork が起動する担当の AI が進めます。この会話を閉じても作業は止まりません。質問や報告は、この会話ではなく画面の「確認待ち」に届きます。この会話で確かめるときは、「確認待ちのタスクを1件ずつ短く教えて」のように頼みます。

## タスクの頼み方の例

| すること | 頼む文の例 |
| --- | --- |
| タスクを頼む | `ログイン画面の不具合を直すタスクを作って進めて` |
| 確認待ちのタスクを見る | `確認待ちのタスクを1件ずつ短く教えて` |
| タスクの状況を聞く | `タスクの状況を教えて` |
| タスクを探す | `README を直したタスクを探して` |
| 質問に答える | `T12 の質問は案2で進めて` |
| 直しを頼む | `T12 のボタンの文をもっと短くして` |
| 完了にする | `T12 は確かめた。完了にして` |
| 保留・中止にする | `T12 を保留にして`、`T12 を中止して` |
| プロジェクトを作る | `~/code/shop をプロジェクトにして` |

タスクは番号（T12 など）か題の言葉で指せます。同じ文は画面の入力欄でも使えます。

## alpacawork そのものの操作

画面を開く・更新する・再起動するといった操作も、この会話で頼めます。ターミナルでは、表のコマンドでも同じことができます。

| すること | 頼む文の例 | コマンド |
| --- | --- | --- |
| 画面を開く | `画面開いて` | `alpacawork open` |
| 動いているか見る | `動いているか見て` | `alpacawork status` |
| 設定を変える | `同時に動かす AI を4つまでにして` | — |
| ふだん使うモデルを変える | `タスクをふだん opus で進めるようにして` | — |
| 新しいモデルを使えるようにする | `Codex の新しいモデルが出たので、選べるようにモデルの設定に足して` | — |
| プロジェクト方針を変える | `プロジェクト方針に「デザインの作成は opus で」と書き足して` | — |
| 最新の版に更新する | `最新の版に更新して` | `alpacawork deploy npm:alpacawork` |
| 止める・起動する・再起動する | `再起動して` | `alpacawork stop`・`start`・`restart` |
| アンインストールする | `アンインストールして` | `alpacawork uninstall` のあと `npm uninstall -g alpacawork` |

会話の最初の1回は、頼む文の前に `/alpacawork` を付けます。設定・モデル・方針の変更は画面の入力欄でも頼め、更新は画面の設定からもできます。止める・再起動する・アンインストールは、画面の入力欄からはできないので、この会話かターミナルで行います。ほかのコマンドと使い方は `alpacawork -h` で確かめられます（詳しくは [開き直す・止める・更新する](manage.md)）。
