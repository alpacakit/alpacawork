## プロジェクトと作業フォルダ

プロジェクトは、AI に作業させるフォルダ1つと、そこでの進め方の約束（プロジェクト方針）です。最初のプロジェクトは、セットアップの3つ目のステップで作っています。

AI は、プロジェクトの「作業フォルダ」で作業します。フォルダにある `AGENTS.md` や `CLAUDE.md`（AI が毎回読む、フォルダごとの指示のファイル）も、AI はここから読みます。

### すでにあるリポジトリで使う

そのリポジトリのフォルダを、プロジェクトの作業フォルダに指定します。中身を移したり、新しく作り直したりする必要はありません。

- **セットアップで作業フォルダを指定しなかったとき**: 画面の左上のプロジェクト名を押し、「（プロジェクト名）の設定…」を開きます。「作業フォルダ」の「選ぶ」でフォルダを選び、「保存」を押します。
- **別のリポジトリでも使うとき**: リポジトリごとにプロジェクトを作ります（[プロジェクトを増やす](#プロジェクトを増やす)）。

作業フォルダを変えたあとは、次に始まる AI の会話から、新しいフォルダで作業します。

AI は確認を求めない設定で、あなたの PC のユーザーの権限で動きます。作業フォルダのファイルを書き換えられ、作業フォルダの外にも届きます。始める前に、リポジトリの変更をコミットしておくと、AI の変更をあとで見分けて戻せます。してほしくないことや、先に聞いてほしいこと（「作業用のブランチで進める」「push は承認なしにしない」など）は、[プロジェクト方針](#プロジェクト方針) に書きます。

### プロジェクトを増やす

仕事やリポジトリごとに、プロジェクトを分けられます。

1. 画面の左上のプロジェクト名を押し、「プロジェクトを作る」を押します。
2. 「名前」と「作業フォルダ」を入れます。「色」は、一覧でプロジェクトを見分けるための色です。
3. 「作る」を押します。プロジェクト方針は、作ったあとにプロジェクトの設定で書きます。

「親プロジェクト」を選ぶと、そのプロジェクトの中に入れ子で作れます。親プロジェクトは、作ったあとでは変えられません。入れ子のプロジェクトは、作業フォルダを空にすると、上のプロジェクトの作業フォルダを使います。

入力欄で「〜のフォルダでプロジェクトを作って」と頼んでも作れます。

### プロジェクトの設定を変える

画面の左上のプロジェクト名を押し、「（プロジェクト名）の設定…」を押します。「設定（歯車）→ プロジェクト」の一覧からも開けます。変えたら「保存」を押します。

| 項目 | 内容 |
| --- | --- |
| 名前、色 | 一覧や画面の上に出る名前と色 |
| 作業フォルダ | AI が作業するフォルダ。空のままにしたときに使われる場所は、欄の下に出ます |
| プロジェクト方針 | AI への約束ごと（[プロジェクト方針](#プロジェクト方針)） |
| 項目 | AI がタスクごとに書くまとめの項目（ゴール、結論、成果物など）と、その順番。ふだんは変えなくてかまいません |

### プロジェクトをアーカイブする・戻す

使わなくなったプロジェクトは、一覧から外せます。プロジェクトの設定のいちばん下の「プロジェクトをアーカイブ」の「アーカイブ…」を押し、確かめる画面で「アーカイブ」を押します。中の入れ子のプロジェクトとタスクも一緒に外れます。記録、ファイル、コードは残ります。

中に、作業中のタスク、報告の確認を待っているタスク、「対応待ち」のタスクがある間と、AI の実行が終わっていない間は、アーカイブできません。先に、完了にするか中止して、実行が終わるのを待ちます。完了や中止になったタスクは、残っていてもアーカイブできます。

戻すときは、「設定（歯車）→ プロジェクト」で、「アーカイブ済み」のプロジェクトを開き、「復元」を押します。入れ子のプロジェクトを別々にアーカイブしたときは、上のプロジェクトを先に復元してから、中のプロジェクトを復元します。

プロジェクトを削除するボタンは、画面にありません。削除は、入力欄でコーディネーターに頼みます。

## プロジェクト方針

「何を任せて、何を聞いてほしいか」は、プロジェクトの設定の「プロジェクト方針」に、普通の文で書きます。書いた文は、そのプロジェクトのすべての担当に伝わります。入力欄で「方針に〜を足して」と頼んでも書けます。

<img src="../images/project-policy-desktop.png" alt="プロジェクトの設定の「プロジェクト方針」の欄。方針が4行書いてある" width="780">

```text
目的: お店のサイトを、スマートフォンで見やすくして公開する
進め方: 見た目に関わる変更は、作る前に見本を見せて聞く
任せること: 進め方、試験、片付けは聞かずに決めて報告する
しないこと: 公開と外部への送信は、承認なしにしない
```

たとえば、AI に勝手に push してほしくないときは、「しないこと: GitHub への push は、承認なしにしない」のように書きます。

その場だけの進め方は、依頼にそのまま書きます（「3案作って比べて」「できたら、別の AI に確かめさせて」）。作業するフォルダにある `AGENTS.md` や `CLAUDE.md`、いま使っているスキルも、AI はいつもどおり読みます。

プロジェクト方針は AI への約束で、仕組みとして止めるものではありません。AI が扱える範囲そのものを限りたいときは、作業用の PC か OS ユーザー（PC にログインするためのアカウント）を分けて、そこで動かします。

記憶（メモリー）のための専用の機能はありません。タスクごとのやり取りは記録に残り、続きを頼むと AI に渡ります。いつも覚えておいてほしいことはプロジェクト方針に書きます。それ以上が要るときは、記憶のためのスキルを入れれば、そのまま働きます。

### 上のプロジェクトの方針

入れ子のプロジェクトの担当には、上のプロジェクトの方針も一緒に伝わります。プロジェクトの設定の「上のプロジェクトの方針（食い違うときは上が優先されます）」を開くと、伝わる内容を読めます。どのプロジェクトにも共通の約束は上のプロジェクトに、そのプロジェクトだけの約束は下のプロジェクトに書きます。

## スキル

スキルは、エージェントに作業の進め方を伝える手順書です。セットアップの2つ目のステップに、タスクを任せやすくするスキルが3つ（askmeclearly、doyourjob、alpacawork-betterquality）、それぞれ何のために入れるかの説明と一緒に表示されます。インストール先はホームフォルダの `~/.agents/skills` で、Claude Code からも使えるようにリンクします。あとで削除できます。

プロジェクトで使われるのは、プロジェクト方針に書かれたスキルだけです。セットアップでは、インストールしたスキルごとに、いつ使うかを添えた1行が方針に入ります。あとから使うときは、入力欄で「このプロジェクトで品質のアドオンを使って」のように頼みます。

majority と try-and-keep は非公開リポジトリで別に配布します。導入済みのものとプロジェクト方針の指定は維持されます。新しく入れるときの権限と手順は [Private add-ons](../../skills/alpacawork/references/setup.md#private-add-ons) にあります。

## 使える AI エージェント

| AI エージェント | 必要なもの |
| --- | --- |
| [Claude Code](https://claude.com/claude-code)、[Codex](https://github.com/openai/codex) | それぞれの CLI でのサインイン |
| [GitHub Copilot](https://github.com/features/copilot) | インストールは要りません（alpacawork に同梱）。GitHub CLI のサインイン（`gh auth login`）で動きます |
| Grok Build（`grok`）、pi（`pi`） | サインイン、または API キー。alpacawork が確かめられるのは、インストールされているかどうかだけで、サインインの状態は確かめられません。Gemini を使うには、pi で `/login` を実行し、Google Gemini の API キーを保存します。[pi のプロバイダー設定](https://pi.dev/docs/latest/providers)を参照してください。 |

この PC にどれが入っているかと、上の3つについてはサインインしてあるかが、セットアップの最初のステップに表示されます。使うものを、そこで有効にします。あとからは、[エージェントの設定を変える](#エージェントの設定を変える) の手順で変えられます。

1つの依頼の中で、設計は Claude Code、実装は Codex のように使い分けられます。

AI エージェントは、いまの契約と設定のまま使います。

- **Claude Code**: `CLAUDE.md`、スキル、MCP、Hooks、記憶（メモリー）を、いつもの置き場からそのまま使います
- **Codex**: 設定、`AGENTS.md`、スキル、MCP、Hooks は、いつものものを使います。会話の履歴と記憶だけを、alpacawork 用の置き場（`~/.codex-alpacawork`）に分けて保存します

alpacawork は無料です。AI の利用料や利用枠は、お使いの AI エージェントの契約のとおりで、同時に動かした分だけ使います。利用上限に達したときのことは、[利用上限に達した](troubleshooting.md#利用上限に達した) にあります。

## エージェントの設定を変える

「設定（歯車）→ サーバー」の「エージェント」を開くと、AI エージェントが1つずつカードで並びます。カードを押すと開きます。変えたあとは、画面の下の「保存」を押します。保存するまでは反映されません。

同じことは、入力欄で頼んでもできます（「Codex も使えるようにして」「Codex のモデル一覧に最新のモデルを追加して」）。

### 有効にする・デフォルトを決める

- **使うかどうか**: カードの「有効」「無効」を切り替えます。無効にすると、新しい依頼はその AI エージェントに行きません。
- **デフォルト**: 「デフォルト」の印が付いた AI エージェントが、特に指定しなかったタスクに使われます。変えるときは、カードを開いて「デフォルトに設定」を押します。
- **サインインが切れたとき**: カードに「サインインしていません。端末で」とコマンドが出ます。そのコマンドを PC のターミナルで実行します。

仕事の種類で使い分けたいときは、プロジェクト方針に書きます（例: 「実装は Codex、できあがりの確認は Claude Code」）。

### モデルやエフォートを足す

各社の新しいモデルが出たときは、自分で追加できます。

1. AI エージェントのカードを開きます。
2. 「依頼のときに選べる値」の `model` の行に、モデルの名前をカンマで区切って足します。名前は、その AI エージェントの CLI でモデルを指定するときの名前です。先頭に書いた値が、新しく始まる AI の会話で、指定が無いときに使われます。エフォートは `effort` の行です。
3. 「保存」を押します。

担当の AI に使わせるには、依頼かプロジェクト方針に、モデルの名前を書きます（「この作業は〜のモデルでやって」）。入力欄の横で選ぶモデルは、コーディネーターのものです（[モデルとエフォート](guide.md#モデルとエフォート)）。

### 実行ファイルの場所を指定する

AI エージェントを入れてあるのに、カードに「実行ファイルが見つかりません:」と出るときは、カードを開き、「実行ファイル」で「ほかの場所」を選んで、実行ファイルの場所を `/` から始まるパスで入れます。場所は、ターミナルで `which claude` のように実行すると分かります。

### API キーを渡す

API キーで動かす AI エージェントには、キーを環境変数ファイルで渡します。キーは秘密なので、入力欄や設定の画面には書かず、自分でファイルに書きます。

1. 「設定（歯車）→ サーバー」のいちばん下の「環境変数ファイル」に出ている場所を確かめます（ふつうは `~/.config/alpacawork/env`）。
2. そのファイルに、`名前=値` の形で1行ずつ書きます（例: `ANTHROPIC_API_KEY=...`）。ファイルが無ければ、新しく作ります。名前は、その AI エージェントの説明書にあります（カードを開くと、公式の説明へのリンクがあります）。
3. ターミナルで、手順1で確かめたファイルに `chmod 600` を実行します（例: `chmod 600 ~/.config/alpacawork/env`）。ほかのユーザーが読める状態だと、読み込まれません。
4. alpacawork を再起動します（[alpacawork を止める・起動する](manage.md#alpacawork-を止める起動する)）。
5. AI エージェントのカードを開き、「追加で渡す環境変数」にその名前があることを確かめます。無ければ足して「保存」を押します。

読み込めたかどうかも、同じ「環境変数ファイル」に出ます（「1 件を反映中」など）。

## 同時に動かす数と実行の上限

最初は、AI が8つまで同時に動く設定です。利用枠を使いすぎるときは、数を減らします。

1. 「設定（歯車）→ サーバー」を開きます。
2. 「高度なオプション」を押して開き、「実行の上限」の「同時に動かす数」を変えます。
3. 「保存」を押します。

上限を超えた分は、順番を待ってから動きます。すでに動いている作業には影響しません。入力欄で「同時に動かす数を4にして」と頼んでも変えられます。

同じ場所に、1回の実行の時間の上限や、AI どうしの自動のやり取りの上限などもあります。項目ごとの意味と初めの値は [設定の一覧](reference.md#サーバー) にあります。

## AI の返事の言語

AI があなたに書く質問や報告の言語は、画面の表示の言語とは別に決まります。初めは、インストールのときに言語を指定していればその言語、していなければ、あなたが最初に書いた文の言語です。変えるときは、入力欄で「これからは日本語で返事をして」のように頼みます。

画面の表示の言語は、「設定（歯車）→ 自分」の「表示言語」で変えます。
