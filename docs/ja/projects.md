# 自分の仕事に合わせる

プロジェクト、方針、使う AI の決め方です。ここにある設定は、どれも入力欄で頼めば AI が変えます（AI へのサインインと API キーだけは自分で行います）。

## すでにあるリポジトリで使う

そのリポジトリのフォルダを、プロジェクトの「作業フォルダ」にします。中身を移す必要はありません。フォルダの `AGENTS.md` や `CLAUDE.md` も、AI はいつもどおり読みます。

あとから変えるときは、画面の左上のプロジェクト名 →「（プロジェクト名）の設定…」→「作業フォルダ」の「選ぶ」→「保存」です。

AI は確認を求めずにファイルを書き換えます。始める前にコミットしておくと、AI の変更を見分けて戻せます。

## プロジェクトを増やす

リポジトリごとにプロジェクトを作ります。左上のプロジェクト名 →「プロジェクトを作る」で、名前と作業フォルダを入れて「作る」を押します。

使わなくなったプロジェクトは、プロジェクトの設定のいちばん下からアーカイブできます。

## プロジェクト方針

AI に任せること、先に聞いてほしいこと、してほしくないことを、プロジェクトの設定の「プロジェクト方針」に普通の文で書きます。そのプロジェクトのすべての AI に伝わります。

用途は `AGENTS.md` と基本的に同じです。alpacawork を使うときだけ AI に読ませたい指示を、プロジェクト方針に書きます。

```text
目的: お店のサイトを、スマートフォンで見やすくして公開する
進め方: 見た目に関わる変更は、作る前に見本を見せて聞く
任せること: 進め方、試験、片付けは聞かずに決めて報告する
しないこと: GitHub への push と公開は、承認なしにしない
```

方針は AI への約束で、仕組みで止めるものではありません。AI が触れる範囲そのものを限りたいときは、作業用の PC か OS のユーザーを分けます。

## 使う AI

| AI エージェント | 要るもの |
| --- | --- |
| Claude Code、Codex | それぞれの CLI でのサインイン |
| GitHub Copilot | GitHub CLI のサインイン（`gh auth login`）。本体は同梱 |
| Grok Build、pi | サインインか API キー |

使う AI は「設定（歯車）→ サーバー」の「エージェント」で有効にして「保存」を押します。仕事で使い分けたいときは、方針に書きます（「実装は Codex、確認は Claude Code」）。

AI の契約と設定は、いまのものをそのまま使います。利用料も契約のとおりです。

## モデルを選ぶ

入力欄の送るボタンの横には、窓口の AI が使うモデルが出ます（例: `opus(low)`）。押すと「設定（歯車）→ サーバー」の「入力欄で話す AI（コーディネーター）」が開き、そこで AI と、止まったときに引き継ぐ代わりの AI を選べます。担当の AI は、同じ画面の「タスクを進める AI」で選びます。作業ごとに替えたいときは、依頼か方針に書きます（「この作業は opus でやって」）。

新しいモデルを足すときは、「設定（歯車）→ サーバー」の「エージェント」でカードを開き、「依頼のときに選べる値」の `model` の行にモデル名を足して「保存」を押します。

## API キーを渡す

キーは入力欄や画面に書かず、自分でファイルに書きます。

1. 「設定（歯車）→ サーバー」のいちばん下の「環境変数ファイル」で場所を確かめます（ふつうは `~/.config/alpacawork/env`）。
2. `ANTHROPIC_API_KEY=...` のように1行ずつ書き、ほかのユーザーが読めないようにします: `chmod 600 ~/.config/alpacawork/env`
3. alpacawork を再起動します（[止める・起動する](manage.md#止める起動する)）。
4. AI のカードの「追加で渡す環境変数」に、その名前があるかを確かめます。無ければ足して「保存」を押します。

## 同時に動かす数

初めは AI が8つまで同時に動きます。利用枠を使いすぎるときは、「設定（歯車）→ サーバー」→「高度なオプション」の「同時に動かす数」を減らして「保存」を押します。
